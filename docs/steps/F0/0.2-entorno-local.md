## Objetivo

Un `make up` levanta toda la infraestructura que NEXUS necesita en local y en CI, sana y con datos de arranque mínimos: PostgreSQL, Kafka + Schema Registry, ClickHouse, Azurite, Keycloak con los usuarios de prueba y un colector OTLP. Los servicios .NET corren fuera de compose (IDE o `dotnet run`); compose solo los construye bajo el perfil `apps` (usado por CI e2e).

**Entregables** (`infra/compose/`)

   Todos con `healthcheck`. Red `nexus`.
2. `keycloak/realm-nexus.json`:
   - Realm `nexus`. Clientes: `nexus-web` (público, Authorization Code + PKCE, redirect `http://localhost:4200/*`), `nexus-mobile` (público, PKCE, redirect `ch.nussli.nexus.mobile:/oauth2redirect`), `nexus-api` (bearer-only; audiencia `api://nexus`). Scope `access_as_user` incluido por defecto en los dos clientes públicos.
   - *Protocol mapper* `oid`: atributo de usuario `oid` → claim `oid` (string) en access token e ID token.
   - Usuarios (contraseña = nombre de usuario, **solo local**), con `oid` fijo que coincide con la semilla dev de 0.4:

| Usuario | `oid` | Uso |
|---|---|---|
| `admin` | `00000000-0000-7000-8000-00000000a001` | GLOBAL (0.6) |
| `usera` | `00000000-0000-7000-8000-00000000a002` | alcance LE-CH |
| `userb` | `00000000-0000-7000-8000-00000000a003` | alcance LE-DE |
| `wha` | `00000000-0000-7000-8000-00000000a004` | solo almacén de LE-CH |
| `unprovisioned` | `00000000-0000-7000-8000-00000000a0ff` | sin `app_user` (ADR-0006: 403) |

3. `.env.example` con todas las variables (contraseñas de desarrollo, puertos) y `make up` que copia `.env.example` a `.env` si no existe.
4. Makefile: `up` (perfil `infra`, espera a que todo esté *healthy*), `down`, `reset` (borra volúmenes), `logs S=<svc>`, `ps`, `doctor`.
5. `tools/doctor.sh`: comprueba Docker y puertos libres, salud de cada contenedor, conexión a PostgreSQL, lista de brokers de Kafka, `GET /subjects` del Schema Registry, `SELECT 1` en ClickHouse, contenedor `documents` creable en Azurite, y obtiene un token de `usera` por *password grant* (solo dev) comprobando que contiene `oid` y `aud` = `api://nexus`.
6. `infra/compose/README.md`: tabla de servicios, URLs y credenciales de desarrollo.
7. CI: el job `e2e` ya puede arrancar `make up` (aunque aún no tenga tests).

**Aceptación I**
- [ ] `make reset && make up` deja todos los contenedores *healthy* en < 3 min.
- [ ] `make doctor` en verde, incluido el token de `usera` con `oid` correcto.
- [ ] Kafka UI muestra el clúster y el Schema Registry sin topics.
- [ ] Ningún puerto choca con los de `architecture.md §6` (gateway 8080 libre).

## Fuera de alcance

Roles y esquemas de PostgreSQL (0.3), topics (0.7), contenedores de servicios .NET (cada servicio añade su entrada al perfil `apps` cuando nace).

## Verificación de Luciano

1. `make reset && make up` → mensaje final "all healthy".
2. `make doctor` → todas las comprobaciones en verde.
3. Abrir `http://localhost:8180` → login en el realm `nexus` con `usera`/`usera` funciona.
4. Abrir `http://localhost:8085` (Kafka UI) y `http://localhost:18888` (Aspire Dashboard).
