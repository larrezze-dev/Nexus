## Objetivo

Reproducir en Azure, de forma declarativa, lo que ya funciona en local: un entorno `dev` con los mismos servicios, la misma base, Kafka con Schema Registry, ClickHouse, Blob, Key Vault, observabilidad e identidad Entra ID, desplegado por CI, sobre el que pasan los mismos tests e2e. Se hace al final de la Fase 0 a propósito: Terraform solo tiene que reproducir una topología probada.

## Track I

Rama `step/0.11-infra`.

**Paso previo:** actualizar ADR-0011 con las respuestas de Luciano (opción de cómputo, Kafka y ClickHouse; región; cargas en edge) y pasarlo a `Aceptado`. Sin eso, no se escribe Terraform.

**Entregables** (`infra/terraform/`)
1. Estado remoto en Azure Storage con bloqueo; `providers.tf` (`azurerm`, `azuread`, `postgresql`, y el proveedor de Kafka/ClickHouse que fije ADR-0011).
2. Módulos: `network` (VNet, subredes, endpoints privados, DNS privado), `compute` (AKS o Container Apps según ADR-0011; ACR), `postgres` (Flexible Server PostgreSQL 17, HA zonal en `prod`, `azure.extensions = btree_gist,pg_trgm`, sin acceso público), `kafka` (según ADR-0011, con Schema Registry y topics desde `contracts/events/topics.yaml` con los parámetros Azure de `conventions-events.md §5`), `clickhouse`, `storage` (Blob `documents`, `erp-exports`; Defender for Storage si DOC-Q2 lo decide), `keyvault` (secretos de los roles `svc_*`; Workload Identity / identidades gestionadas por servicio), `observability` (Log Analytics + Application Insights con OTLP), `identity` (registros de aplicación: API `api://nexus` con scope `access_as_user`, SPA `nexus-web`, público `nexus-mobile`; el claim `oid` es nativo).
3. `envs/dev` (y esqueleto de `envs/prod` sin aplicar).
4. Bootstrap de la base: el `00_roles.sql` de 0.3 ejecutado por un job de despliegue con identidad administradora, contraseñas desde Key Vault.
5. Pipeline de despliegue (`.github/workflows/deploy-dev.yml`): OIDC federado a Azure (sin secretos de larga duración), `terraform plan` en PR / `apply` en `main` con aprobación manual, build y push de imágenes, `flyway migrate` como job, despliegue de servicios, migraciones de ClickHouse (las aplica `nexus-projections`), e2e de humo.
6. `infra/arc/`: manifiestos y README para conectar un clúster Kubernetes de almacén a Azure Arc; **sin cargas desplegadas** en este paso salvo que ADR-0011 diga lo contrario.
7. Configuración de la app web y del gateway para Entra ID (`authority` del tenant, `clientId`, audiencia) por variables.

**Aceptación I**
- [ ] `terraform plan` limpio en `envs/dev` tras `apply`.
- [ ] Ningún recurso de datos con acceso público (comprobado con Azure Policy o una consulta de Resource Graph en el pipeline).
- [ ] Los e2e de 0.4, 0.6, 0.9 y 0.10 pasan contra `dev` con usuarios reales de Entra ID de prueba.
- [ ] Rotar la contraseña de `svc_platform` en Key Vault y reiniciar el servicio no requiere cambios de código.
